# 视频脚本入库规范（v1）

一条视频 = 一个 markdown（`scripts/episodes/<EP>-<汉字>.md`）。**除了这个文件，不需要改任何代码**。

## 1. 文件命名

```
scripts/episodes/A-001-火.md      # <线号>-<三位序号>-<主字>
```

- 线号：`A` 汉字拆解 / `B` 词 / `C` 成语 / `D` 诗（对应策划案 §2 四条内容线）。
- 序号按线递增，**不复用、不重排**：删掉的集号留空，避免已发布视频的编号错位。
- 文件名里的汉字是给人看的；程序读写的是 front matter 里的 `ep` / `slug`。

## 2. front matter（必填）

| 字段 | 必填 | 说明 |
|---|---|---|
| `ep` | ✅ | `A-001`，全局唯一，与文件名一致 |
| `line` | ✅ | `A` / `B` / `C` / `D` |
| `slug` | ✅ | 小写 ASCII，产物文件名用（`huo` → `A-001-huo.mp4`） |
| `title_en` | ✅ | 直接当 YouTube/TikTok 标题用，**钩子词必须在前 5 个词内** |
| `title_zh` | ✅ | 内部中文名，不上线 |
| `hanzi` | ✅ | 本集主字/词 |
| `pinyin` | 建议 | 主字拼音 |
| `topic_id` | ✅ | 对应 `scripts/选题库/topics.json` 的 `id`；**没有选题号不允许入库** |
| `platform` | ✅ | `双` = YouTube + TikTok 同发；`YT` = YouTube 优先；`TT` = TikTok 优先 |
| `duration_target` | 建议 | 目标秒数，硬上限 60 |
| `voice` | 可选 | 配音音色（默认 `Serena`） |
| `status` | ✅ | `draft` → `reviewed` → `rendered` → `published` |

## 3. 分镜表（必填）

```markdown
| time | vo_en | onscreen_zh | visual |
|---|---|---|---|
| 0:00 | Three thousand years ago, someone scratched fire onto a bone. | 火 | 纸纹底，一个大字 |
```

- `time`：`mm:ss`，**只写起点**。每段时长 = 下一段起点 − 本段起点；最后一段自动 +5s。配音比这一格长时，渲染器自动延长该段（不会截断旁白）。
- `vo_en`：逐句英文旁白，**一句话一行**（中文解说和拼音不要混进来）。留空 = 该段无人声。
- `onscreen_zh`：屏幕上出现的文字，`<br>` 换行；第一个 `·` 之前的部分会被当成大字放大显示。
- `visual`：给人看/给剪辑看的画面说明，渲染器只用来生成占位帧，正文体量由素材目录决定。

## 4. 硬规则（踩了就退回）

1. **时长 ≤ 60s**：>1 分钟且带版权声明的 Short 会被全球屏蔽（策划案 §2 已锁规则）。
2. **钩子 0–3s 不得出现 "Chinese character"**：观众已经知道在看什么。
3. **一句一事实**：每条只交付一个「原来如此」，出现第二个知识点就拆成两条。
4. **有出处**：`## 考据备注` 必须写依据（工具书/论文），没有依据的说法不写。
5. **素材对齐**：`assets/字源图/<EP>/` 里的文件必须与 `## 素材清单` 一一对应，缺图不许标 `status: rendered`。

## 5. 从选题到成片的完整动作

```bash
# 1) 从选题库挑一条，建文件
cp scripts/episodes/_模板.md scripts/episodes/A-002-尖.md   # 改 front matter

# 2) 写分镜表 → 过「三问」（依据？异说？冒犯？）

# 3) 无声验版式（30 秒）
./make.sh A-002 --none

# 4) 出正式版（本机 Qwen3-TTS）
./make.sh A-002

# 5) 复核产物
#    renders/成片/A-002-jian.mp4 + .json 清单
#    subtitles/A-002-jian.srt
```

产物 JSON 清单（`renders/成片/<EP>-<slug>.json`）记录时长、段数、配音模式，用于上线前核对，也是发布台账的原始数据。

## 6. 与选题库的对应关系

`topics.json` 里每条只加一个 `status` 字段维护进度（`todo` / `scripted` / `published`），
**新选题一律先入库拿号，再写脚本**。这样任何时候 `topics.json` 都是一份可信的产能台账：
有几条待写、几条已成片、几条已发布，一条 SQL 级别的 `jq` 就能查出来。
